# Партнерська (реферальна) програма

Партнери — **схвалені B2B-клієнти** (кабінет `/b2b/`). На вкладці «Партнерська програма» клієнт
погоджується з правилами й отримує код (6 символів, напр. `A7K2P9`). Покупець, що перейшов за
посиланням `?ref=КОД`, закріплюється за партнером на строк cookie (30 днів). Коли таке замовлення
виконано і минув період повернення (14 днів), партнер отримує бали. Бали витрачаються на власні
замовлення в B2B-кабінеті або виводяться грошима (заявку менеджер обробляє вручну).

Сповіщення email немає: адміну приходить Telegram (новий партнер, заявка на виплату, партнерське
замовлення), партнер бачить усе в кабінеті.

## Як це влаштовано

| Що | Де |
|---|---|
| Таблиці, розрахунок, статуси, баланс, виплати (уся грошова логіка) | `scripts/supabase/affiliate_schema.sql` |
| Перевірка сценаріїв на тестовій БД у пам'яті | `scripts/supabase/affiliate_test.mjs` + `affiliate_test.sql` |
| Кліки, кабінет партнера, адмін-дії | Edge Function `supabase/functions/affiliate` |
| Прив'язка замовлення з сайту до партнера | `supabase/functions/order-submit` (поле `aff`) |
| Оплата балами в кошику B2B | `supabase/functions/b2b` (поле `points` у дії `order`) |
| Трекінг на сторінках, кнопка «Скопіювати моє посилання» на сторінці товару | `assets/js/affiliate.js` (+ `cart.js` додає cookie до замовлення) |
| 301 з `?ref=КОД` на чисту адресу | `.htaccess` — генерує `scripts/generate_static_pages.js` (`affiliateRules()`) |
| Кабінет партнера | `b2b/index.html`, вкладка «Партнерська програма» (`/b2b/#partner`) |
| Адмінка | `affiliate-admin/` — розділ «Партнерка» |
| Публічна сторінка (UA/EN, умови беруться з налаштувань) | `partnerska-programa.html` (+ 301 з `/partnerska-programa/`) |

### Шлях покупця

1. `https://avtonomka.com.ua/product/...?ref=A7K2P9&utm_source=tg` → `.htaccess` робить **301** на
   `.../product/...?utm_source=tg#aff=A7K2P9`. Фрагмент `#...` пошуковики не індексують, тож дублів сторінок немає.
2. `affiliate.js` забирає код із `#aff=` (або з `?ref=`, якщо 301 не спрацював), прибирає його з адреси
   й надсилає в `affiliate` (дія `click`). Функція перевіряє код (невідомий чи заблокований мовчки
   ігнорує), пише перехід в `affiliate_clicks` (повтор з того ж IP+UA за 24 год не пишеться, понад 30
   переходів з IP за годину теж) і повертає підписану cookie `aff_ref` = `КОД.час.підпис` на `cookie_days`.
   **Last click**: новий код перезаписує cookie; **first click**: діюча cookie лишається.
3. Під час оформлення кошика чи швидкої заявки `cart.js` додає cookie в поле `aff`. `order-submit`
   перевіряє підпис і строк, а `affiliate_on_new_order()` створює нарахування «Очікує».
   Без cookie запит і замовлення такі самі, як і раніше.

> Cookie ставить JS, а не сервер, тож вона без HttpOnly: замовлення йде з браузера прямо на
> `supabase.co`, і JS має її прочитати. Підробити cookie не можна (HMAC-підпис з `AFFILIATE_SECRET`),
> а строк дії перевіряє сервер.

### Розрахунок

* База — сума позицій замовлення (`order_items`, ціни після знижок; доставка в суму не входить),
  мінус оплачене балами.
* Ставка позиції: **товар → категорія → індивідуальна партнера → загальна**. Категорія — `product_type`
  з `products.json`.
* Ставки фіксуються в нарахуванні (`rates_snapshot`) на момент замовлення: зміна налаштувань історію
  не перераховує. Товар, який менеджер додав у замовлення пізніше, рахується за індивідуальною або загальною ставкою, що діяла в момент замовлення.
* Бали = сума по позиціях, округлена вниз. 1 бал = `point_value` грн.
* Менеджер змінює товари чи кількість у розділі «Замовлення» → нарахування перераховується.
  Якщо його вже підтверджено, різниця йде в журнал (часткове повернення — сторно на різницю).

### Статуси

| Подія в замовленні | Нарахування |
|---|---|
| Створено | `pending` — «Очікує» |
| «Виконано» + `hold_days` | `approved` — бали в журналі |
| «Скасовано» / «Повернення» до підтвердження | `cancelled` |
| «Повернення» / «Скасовано» після підтвердження | `reversed` — сторно, баланс може піти в мінус |
| Замовлення відновили зі скасованого | знову `pending` |

`pending → approved` виконують `pg_cron` раз на добу (03:15 UTC), тригер при статусі «Виконано»
(при `hold_days = 0`) і кожне відкриття розділу «Партнерка» чи вкладки партнера в кабінеті.

### Баланс

Баланс — сума журналу `affiliate_transactions`: `commission`, `reversal`, `spend` (оплата замовлення),
`spend_refund` (скасоване замовлення, оплачене балами), `payout` (заявка: сума резервується одразу),
`payout_refund` (заявку відхилено), `adjustment` (ручне коригування з коментарем). Усі списання
блокують рядок партнера (`select ... for update`) — одночасні запити не спишуть двічі.

Заявка на виплату: не менше `min_payout` грн і лише одна необроблена. Реквізити (IBAN або картка,
ПІБ, ІПН) шифруються у функції `affiliate` (AES-GCM, ключ з `AFFILIATE_SECRET`). В адмінці їх видно
лише після натискання «Показати реквізити», і кожен такий перегляд пишеться в журнал дій.

Партнер не бачить даних покупця: у кабінеті лише дата, частково прихований номер замовлення, сума-база, % і бали.

Гуртові замовлення з кабінету `/b2b/` партнерам не нараховуються. Самореферал (замовлення з телефону
самого партнера) теж не враховується.

## Розгортання

1. **SQL.** Supabase → SQL Editor → вставити `scripts/supabase/affiliate_schema.sql` → Run.
   Потім ще раз запустити `scripts/supabase/b2b_schema.sql`: він додасть обмежувальну політику
   «no b2b clients» і на нові таблиці.
2. **pg_cron.** Dashboard → Database → Extensions → увімкнути `pg_cron` → ще раз запустити
   `affiliate_schema.sql` (розділ 8 створить задачу `affiliate-approve`). Перевірка:
   `select jobname, schedule from cron.job;`
3. **Секрет.** Edge Functions → Secrets → `AFFILIATE_SECRET` = довгий випадковий рядок
   (напр. результат `openssl rand -base64 48`). **Не змінювати після запуску**: старі cookie стануть
   недійсними, а збережені реквізити не розшифруються.
4. **Функції.** Edge Functions → Deploy a new function → Via Editor:
   * **`affiliate`** — вставити `supabase/functions/affiliate/index.ts` → Deploy
     (JWT-перевірку лишити **увімкненою**: сайт надсилає anon-ключ);
   * передеплоїти **`order-submit`** і **`b2b`** з оновлених файлів.
5. **Сайт.** Влити гілку в `master` → деплой сам підтягне `.htaccess`, сторінки й скрипти.
6. **Налаштування.** Адмінка → «Партнерка» → «Налаштування»: відсотки по категоріях і текст правил
   (нижче — шаблон). Без тексту правил партнер бачить посилання на `partnerska-programa.html`.

### Перевірка після деплою

* `curl -sI 'https://avtonomka.com.ua/catalog.html?ref=A7K2P9&utm_source=x'` → `301`,
  `Location: /catalog.html?utm_source=x#aff=A7K2P9`. Якщо 301 немає (сервер не прийняв правило),
  трекінг усе одно працює: `affiliate.js` бере `?ref=` з адреси, тільки без 301 для SEO.
* Відкрити посилання партнера в приватному вікні → DevTools → Application → Cookies: `aff_ref`;
  у «Партнерці» на картці партнера кількість переходів +1.
* Оформити тестове замовлення → у Telegram-сповіщенні рядок «🤝 Партнер: КОД», в адмінці «Нарахування» — «Очікує».
* Тести логіки (без бойової БД):
  ```
  npm i --no-save @electric-sql/pglite@0.2.17
  node scripts/supabase/affiliate_test.mjs
  ```

### Назва параметра `ref`

Параметр захардкоджено в трьох місцях: `AFFILIATE_PARAM` у `scripts/generate_static_pages.js`
(правила `.htaccess`), `PARAM` в `assets/js/affiliate.js`, `AFF_PARAM` у `b2b/index.html`. Щоб змінити,
поправте всі три й перезапустіть генератор. В адмінці назву параметра лише показано.

## Шаблон правил (вставити в «Налаштування» і відредагувати)

```
1. Учасником програми може бути клієнт B2B-кабінету Автономки, який погодився з цими правилами.
2. Партнер отримує персональний код і посилання. Покупець, що перейшов за посиланням, закріплюється за партнером на строк дії посилання, вказаний в умовах.
3. Винагорода нараховується у балах від суми товарів у замовленні після знижок, без вартості доставки, за ставками, що діяли на момент замовлення.
4. Нарахування стає доступним після виконання замовлення і закінчення періоду повернення. Якщо замовлення скасовано або повернено, нарахування анулюється, у тому числі після підтвердження.
5. Не нараховується за власні замовлення партнера, замовлення з B2B-кабінету та замовлення, отримані недобросовісно (спам, введення в оману, контекстна реклама на бренд «Автономка»).
6. Бали можна використати для оплати власних замовлень у B2B-кабінеті або вивести на рахунок ФОП чи картку від мінімальної суми. Виплати обробляються вручну протягом 5 робочих днів.
7. Автономка може змінювати умови програми; зміни не впливають на вже створені нарахування. За порушення правил участь може бути призупинено.
```
