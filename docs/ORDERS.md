# Замовлення: розділ адмінки і підключення

Усі замовлення (кошик сайту, швидка заявка на сторінці товару, мініапп у
Telegram) зберігаються в Supabase і обробляються в адмінці:
**https://avtonomka.com.ua/orders-admin/**. Менеджеру в Telegram приходить
повідомлення про кожне нове замовлення з посиланням на нього.

Google Таблиця «Заявки» лишається **запасною копією**: сайт і мініапп і далі
шлють туди кожне замовлення. Якщо Supabase недоступний, замовлення не губиться.

## Як це влаштовано

```
кошик (checkout.js) ─┐                                  ┌─> orders / order_items  ─> адмінка orders-admin/
швидка заявка        ├─> Edge Function order-submit ────┤
(order-form.js)      │   (перевірка, захист від дублів)  └─> повідомлення менеджеру в Telegram
мініапп ─────────────┘
        └──────────────> Google Таблиця «Заявки» (запасна копія)
```

| Файл | Що робить |
|---|---|
| `scripts/supabase/orders_schema.sql` | таблиці `orders`, `order_items`, `order_history`, тригер історії, `save_order_items()`, доступ лише адмінам |
| `supabase/functions/order-submit/index.ts` | приймає замовлення, перевіряє поля, відсіює дублі, пише в базу і менеджеру |
| `assets/js/cart.js` → `window.Orders` | надсилання з сайту: Supabase + Google Таблиця |
| `assets/js/checkout.js`, `assets/js/order-form.js` | кошик і швидка заявка; клієнт бачить номер замовлення |
| `miniapp_v/index.html` | замовлення з мініаппа (з підписом Telegram - видно, хто замовив) |
| `orders-admin/index.html` | розділ «Замовлення» адмінки |

## Підключення (один раз, ~10 хвилин)

Поки ці кроки не виконано, сайт працює як раніше: замовлення йдуть лише в
Google Таблицю, а розділ адмінки пише, що таблиць ще немає.

### 1. Таблиці

Supabase → **SQL Editor** → New query → вставити весь
`scripts/supabase/orders_schema.sql` → **Run**. Має бути «Success».
(Потрібен уже виконаний `miniapp_tracking_schema.sql` - він є.)

Перевірка там же:

```sql
select count(*) from public.orders;          -- 0
select public.normalize_phone('067 123 45 67'); -- 380671234567
```

### 2. Функція

Supabase → **Edge Functions → Deploy a new function → Via Editor** →
назва **`order-submit`** → замінити код вмістом
`supabase/functions/order-submit/index.ts` → **Deploy**.

Потім у функції → **Details / Settings** → вимкнути **Enforce JWT
verification** → Save (сайт надсилає замовлення без входу в Supabase).

Секрети додавати не треба: функція бере ті самі, що й бот -
`TELEGRAM_BOT_TOKEN` і `MANAGER_CHAT_ID` (кому слати сповіщення).

### 3. Перевірка

1. Оформити тестове замовлення на сайті (кошик → «Підтвердити замовлення»).
   Після надсилання має з'явитися «Номер замовлення: №1001».
2. Менеджеру в Telegram приходить «🛒 Нове замовлення №1001» з кнопкою-посиланням.
3. Адмінка → **Замовлення**: замовлення в списку зі статусом «Нове».
4. Тестове замовлення можна видалити в картці («Видалити замовлення»).

Якщо номер не з'явився, а «Дякуємо» є - замовлення дійшло лише в Google
Таблицю: перевірте, що функція називається саме `order-submit` і JWT-перевірку
вимкнено (Edge Functions → order-submit → Logs покаже помилку).

## Робота в адмінці

- **Список**: номер, дата, клієнт, товари, сума, джерело, статус. Нові
  замовлення підсвічені, їх кількість - у назві вкладки браузера. Список
  оновлюється сам щохвилини.
- **Фільтри**: статус (вкладки з лічильниками), джерело, період; пошук за
  номером, ім'ям, телефоном (будь-який запис), ТТН, товаром.
- **Картка** (клік по рядку або посилання з Telegram `orders-admin/#1001`):
  - статус: Нове → В роботі → Підтверджено → Оплачено → Відправлено → Виконано,
    або Скасовано / Повернення;
  - клієнт: ім'я, телефон, місто, відділення НП, оплата (можна виправити),
    кнопки «Подзвонити», Telegram (для мініаппа), «Копіювати телефон»;
    коментар клієнта;
  - ТТН Нової Пошти з кнопкою «Відстежити»; нотатка менеджера;
  - товари: змінити кількість і ціну, прибрати, додати (підказки з каталогу
    сайту або свій текст); сума перераховується;
  - **історія**: коли створено і кожна зміна статусу, ТТН, нотатки, даних
    клієнта, товарів (що було → що стало);
  - **інші замовлення клієнта** за тим самим телефоном і загальна сума.
  - «Зберегти» з'являється після змін; вийти з незбереженими змінами сторінка
    не дасть без підтвердження.
- **Експорт CSV** - поточний відфільтрований список (відкривається в Excel).
- Видалення - лише для спаму й тестів; для відмов - статус «Скасовано».

## Захист

- Сайт і мініапп не мають доступу до таблиць напряму: лише функція
  `order-submit` (ключ service_role) пише замовлення.
- Читати й змінювати замовлення можуть лише адміни (`tg_admins`, як для
  мініаппа). Додати адміна - docs/ADMIN.md / `miniapp_tracking_schema.sql`.
- Повторне надсилання того самого замовлення (подвійний клік, повтор після
  помилки мережі) не створює дубль: у кожного замовлення свій ключ.
- Не більше 5 замовлень з одного телефону за 10 хвилин.
- Ціни в замовленні - з кошика клієнта (як на сторінці в момент додавання);
  менеджер бачить і може виправити їх у картці.

## Далі (коли знадобиться)

- Автоматичний статус доставки за ТТН (потрібен API-ключ Нової Пошти).
- Імпорт старих замовлень з Google Таблиці (рядки одного кошика об'єднуються
  за «№ замовлення»).
