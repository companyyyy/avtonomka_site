# B2B-кабінет: партнери, гуртові ціни, замовлення

Кабінет для дилерів, монтажників і магазинів: **https://avtonomka.com.ua/b2b/**.
Партнер входить за email і паролем, бачить каталог з гуртовими цінами і
оформлює замовлення. Менеджер веде партнерів в адмінці:
**https://avtonomka.com.ua/b2b-admin/** (пункт меню «B2B»).

Актуально на 2026-10-30.

## Як пов'язані ціни

Окремого «B2B-прайсу» немає - є одна гуртова ціна на товар, і з неї
рахується все гуртове:

```
фід постачальника (dfi2) ──► роздрібна ціна сайту ──► prom_file.xml та клієнтські фіди від роздрібу
                                  (щогодини, автоматично)

/prom-admin/ «Ціна гурт, $» × курс ──┬──► feed/opt.xml і клієнтські фіди від опту
   (data/ultradomik/prices.json)     └──► ціни в B2B-кабінеті
```

- Змінили «Ціна гурт, $» або курс у «Ціни Prom» → за 1-2 хв змінюється і
  `feed/opt.xml`, і ціна в кабінеті (кабінет читає ті самі файли з сайту, кеш - 1 хв).
- Галочка «У фідах» (вимкнути товар) - у кабінеті товар «під замовлення».
- Товар без гуртової ціни в кабінеті є, але з ціною «за запитом».
- Фід постачальника містить **лише роздрібну** ціну, тому сам гурт від нього не
  залежить і вводиться вручну. Змінити ціну «в прайсі постачальника» з нашого
  боку неможливо - це їхній файл, ми його лише читаємо.

## Коди товарів

Код товару = **id постачальника − 140 000**: `152517` → `12517`, `142723` → `2723`.
Назад: код + 140 000. Порядкових номерів немає, тож нові товари нічого не зсувають.
Товари, які ми завели самі (`ud-avr-2p` тощо), лишаються зі своїм id.

Код показано: у B2B-кабінеті (колонка «Код», пошук за кодом), у «Ціни Prom»
(перша колонка, під ним дрібно - id постачальника), у замовленнях B2B (поле
артикулу позиції і Telegram-сповіщення - `[12517] Назва`).

URL сторінок товарів, id у фідах Prom і `products.json` **не змінено** - там
лишився id постачальника: зміна id у фіді змусила б Prom і клієнтів-перекупників
перестворити всі товари.

Константа `CODE_OFFSET` - у `supabase/functions/b2b/index.ts` і
`prom-admin/index.html`. Якщо з'явиться другий постачальник з іншою нумерацією,
коди треба буде розвести (наприклад, свій зсув для кожного).

## Доступ партнерів

Два шляхи:

1. **Заявка** - на `/b2b/` вкладка «Стати партнером» (компанія, ЄДРПОУ,
   контакт, телефон, email). Менеджеру приходить сповіщення в Telegram, заявка
   з'являється в «B2B» → «Заявки». «Схвалити і створити вхід» → адмінка показує
   логін і пароль, кнопка «Копіювати» - передати партнеру.
2. **Менеджер сам** - «B2B» → «+ Додати клієнта» → те саме, без заявки.

У картці клієнта: редагування даних, нотатка менеджера, «Новий пароль»,
«Заблокувати» / «Розблокувати», «Відхилити» заявку. Пароль показується лише
один раз, у момент створення; забув - «Новий пароль».

Відкриту реєстрацію в Supabase Auth **не вмикати** - заявки йдуть через
функцію, а вхід створює лише менеджер.

## Замовлення

Замовлення з кабінету потрапляють у ту саму таблицю `orders`, що й з сайту,
з джерелом **«B2B»** - обробляються в розділі «Замовлення» як звичайно (статуси,
ТТН, історія). Ціни позицій рахує сервер (не браузер), за поточним гуртом.
Партнер бачить свої замовлення і їх статуси у вкладці «Мої замовлення».

## Безпека

- B2B-партнер - користувач Supabase Auth з `app_metadata.role = 'b2b'` (ставить
  лише сервер). Частина старих політик бази пускає будь-кого залогіненого
  (статті, коментарі, аукціон, Storage), тому `b2b_schema.sql` додає на кожну
  таблицю обмежувальну політику «не B2B». **Нова таблиця, створена пізніше** -
  запустити `b2b_schema.sql` ще раз.
- В адмінку B2B-акаунт не пускає `admin-shell.js`; у кабінеті - власна сесія
  (`storageKey: avtonomka-b2b-auth`), не змішується з адмінською.
- ⚠ Гуртові ціни **вже зараз публічні**: `feed/opt.xml` і
  `data/ultradomik/prices.json` відкриваються без входу. Якщо гурт має бачити
  лише партнер - окреме рішення (сховати opt.xml за секретним посиланням і
  прибрати `wholesale_usd` з публічного файлу).

## Файли

| Файл | Що робить |
|---|---|
| `scripts/supabase/b2b_schema.sql` | таблиця `b2b_clients`, `is_b2b_client()`, `orders.b2b_client_id`, захист інших таблиць |
| `supabase/functions/b2b/index.ts` | заявка, каталог з цінами, замовлення, мої замовлення, дії адміна (створення входу, блокування) |
| `b2b/index.html` | кабінет партнера |
| `b2b-admin/index.html` | розділ адмінки «B2B» |

## Підключення (один раз, ~10 хвилин)

1. **SQL**: Supabase → SQL Editor → New query → вставити весь
   `scripts/supabase/b2b_schema.sql` → Run. Потрібні вже виконані
   `miniapp_tracking_schema.sql` і `orders_schema.sql`.
2. **Функція**: Edge Functions → Deploy a new function → Via Editor → назва
   **`b2b`** → вставити `supabase/functions/b2b/index.ts` → Deploy.
   «Enforce JWT verification» лишити **увімкненим** (кабінет завжди шле ключ).
   Секрети ті самі, що в `order-submit` (`TELEGRAM_BOT_TOKEN`, `MANAGER_CHAT_ID`).
3. **Сайт**: файли `b2b/`, `b2b-admin/` потрапляють на сайт з комітом як завжди.
4. **Перевірка**:
   - адмінка → «B2B» → «+ Додати клієнта» з тестовим email → з'являються логін/пароль;
   - `/b2b/` → увійти ним → каталог з цінами (ціна = «Ціна гурт, $» × курс);
   - покласти товар, «Оформити» → номер замовлення, сповіщення в Telegram,
     замовлення в «Замовлення» з джерелом B2B;
   - тим самим логіном спробувати `admin.html` → має не пустити;
   - тестового клієнта - «Заблокувати», тестове замовлення - видалити.
