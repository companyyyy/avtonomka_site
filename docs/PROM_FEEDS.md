# Фіди Prom і адмінка цін (/prom-admin/)

Опис усього функціоналу фідів для Prom.ua: які фіди є, як рахуються ціни й
наявність, як працює адмінка і що запускається автоматично. Написано так, щоб
за цим описом можна було зробити те саме на іншому сайті.

Актуально на 2026-10-15. Код: `scripts/generate_ultradomik_feed.py`,
`scripts/sync_ultradomik_prices.py`, `prom-admin/index.html`,
`.github/workflows/prom-feed.yml`, `.github/workflows/update.yml`.

---

## 1. Що це і навіщо

Сайт віддає XML-фіди для імпорту в Prom.ua. Кожен клієнт (перекупник) отримує
своє посилання на фід і вказує його у своєму кабінеті Prom. Prom сам забирає
файл за своїм розкладом.

Усі фіди мають **однакові товари, тексти, фото й категорії**. Відрізняється
лише **ціна** (а у фіду опту ще й набір товарів, див. 4.3).

Шеф керує всім у веб-адмінці `/prom-admin/`, а не в коді:

- роздрібна ціна товару (підтягується з сайту, можна змінити вручну);
- гуртова ціна в доларах і курс долара;
- вимкнути товар у всіх фідах;
- створити / змінити / видалити клієнтський фід з правилом ціни.

## 2. Фіди

| Фід | Файл | Ціна |
|---|---|---|
| Роздріб (основний) | `prom_file.xml` | роздрібна ціна + випадкові 1-10 грн |
| Опт | `feed/opt.xml` | гуртова ціна $ × курс (та сама ціна - у B2B-кабінеті, docs/B2B.md) |
| Клієнтські фіди | `invertorshop.xml`, `feed/<назва>.xml` | правило з адмінки (див. 4.2) |

Посилання: `https://<сайт>/<файл>`. Файл клієнтського фіду не змінюється, навіть
якщо змінити назву чи правило ціни, тож посилання в кабінеті клієнта не ламається.

Інші фіди сайту (Google Merchant `feed.xml`, `feed/bezpeka.xml`) будуються
окремо, з цін сайту; в адмінці вони лише показані зі посиланнями.

## 3. Дані (усе - JSON-файли в репозиторії)

Сайт статичний, бекенду немає. Адмінка читає й пише ці файли через GitHub API
(див. розділ 6), а генератор на GitHub Actions збирає з них XML.

### 3.1 `data/ultradomik/prices.json` - ціни й наявність, ключ - id товару

```json
{
  "152517": {
    "price": 11477,          // роздрібна ціна, грн (з сайту; можна змінити вручну)
    "in_stock": true,        // наявність на сайті (з сайту)
    "wholesale_usd": 210,    // гуртова ціна, $ (лише вручну; 0 = немає)
    "off": true              // знята галочка «В наявності» (лише вручну)
  }
}
```

| Поле | Хто пише | Автооновлення сайту |
|---|---|---|
| `price` | сайт / адмінка | **перезаписує** ціною сайту |
| `in_stock` | сайт | **перезаписує** наявністю сайту |
| `wholesale_usd` | адмінка | не чіпає |
| `off` | адмінка | не чіпає |

### 3.2 `data/ultradomik/feeds.json` - клієнтські фіди і курс

```json
{
  "feeds": [
    { "file": "invertorshop.xml",    "name": "ІнверторШоп", "percent": 35 },
    { "file": "feed/enerhiia24.xml", "name": "Енергія24",   "percent": 0, "add_min": 1, "add_max": 200 },
    { "file": "feed/petrovfop.xml",  "name": "PetrovFOP",   "percent": 16, "base": "wholesale" }
  ],
  "usd_rate": 45.3
}
```

| Поле | Значення |
|---|---|
| `file` | шлях файлу фіду; `feed/<латиниця>.xml`, задається один раз при створенні |
| `name` | назва для адмінки |
| `percent` | ± відсоток, від −90 до +500 |
| `add_min`, `add_max` | випадкова надбавка в грн, цілі числа, `add_min ≤ add_max`, можна мінусові; обидва або жодного |
| `base` | `"wholesale"` = рахувати від гуртової ціни; немає поля = від роздрібної |
| `cat_percent` | `{"<id категорії>": відсоток}` - свій відсоток для категорії замість `percent` (напр. `{"11": 10, "2": 20}`: комплекти +10%, акумулятори +20%); категорії без запису беруть `percent`. Задається кнопкою «Категорії» біля фіду в адмінці. Id - `CATEGORIES` у генераторі |
| `usd_rate` | курс $ для гурту, 1-1000; за замовчуванням 45 |

### 3.3 `data/ultradomik/products.json` - тексти товарів, написані вручну

Список позицій з українськими й російськими текстами для Prom: назва, абзаци
опису, характеристики, ключові слова, категорія, виробник, артикул.

```json
{
  "sheet": "Must PV18-1512 VPM II 1.5 кВт 12 В",   // назва з прайсу (для звіту)
  "ids": ["152517"],                                // id товарів сайту
  "cat": 1,                                         // категорія фіду (див. 5.4)
  "vendor": "MUST", "code": "PV18-1512VPM II",
  "name_ua": "...", "name_ru": "...",
  "p_ua": ["абзац", "..."], "p_ru": ["абзац", "..."],
  "specs": [["Назва UA", "Назва RU", "значення UA", "значення RU (необов'язково)"]],
  "kw_ua": "ключові, слова", "kw_ru": "ключевые, слова"
}
```

Позиція з `"feed_only": true` - товар, якого немає на сайті (лише у фідах), id
свій (напр. `ud-avr-2p`); ціну й наявність для нього задають тільки в адмінці.

### 3.4 Службові файли (пише генератор)

- `data/ultradomik/feed_items.json` - список товарів для таблиці адмінки:
  `{id, name, cat, photo, problem, site}`. `problem` - чому товар не йде у фід
  («немає товару на сайті», «немає фото на білому фоні»); `site` - чи є картка на сайті.
- `data/ultradomik/feeds_built.json` - які файли фідів генератор створив
  минулого разу (щоб видаляти файли фідів, прибраних в адмінці, і нічого іншого).
- `assets/images/feed-auto/<id>.jpg` - зібрані фото комплектів (див. 5.3).

## 4. Логіка цін і наявності

### 4.1 Роздріб і опт

- **Роздріб `prom_file.xml`**: `price + random(1..10)` грн. Випадкова сума нова
  для кожного товару при кожній генерації.
- **Опт `feed/opt.xml`**: `round(wholesale_usd × usd_rate, 2)` грн, без
  надбавок. Товар з `wholesale_usd` = 0 або порожнім **у фід опту не йде**.

### 4.2 Клієнтський фід

Береться основа:

- `base` немає (роздріб): основа = `price`;
- `base: "wholesale"` (опт): основа = `wholesale_usd × usd_rate`; товари без
  гуртової ціни у фід не йдуть.

Далі:

| Правило | Ціна у фіді |
|---|---|
| лише відсоток, від роздрібу | `(price + та сама випадкова 1..10, що й у prom_file.xml) × (1 + percent/100)` |
| відсоток і/або надбавка, від роздрібу | `max(1, price × (1 + percent/100) + random(add_min..add_max))` |
| від опту | `max(1, опт_грн × (1 + percent/100) + random(add_min..add_max) або 0)` |

Якщо для категорії товару є `cat_percent`, у формулах замість `percent` береться він.
Випадкова надбавка своя для кожного товару і нова при кожній генерації.
Ціна у XML - з крапкою і двома знаками (`12345.00`).

### 4.3 Наявність (`<available>`)

```
available = НЕ off  І  (in_stock  АБО  товару немає на сайті)
```

- Знята галочка в адмінці (`off: true`) - товар «немає в наявності» **в усіх
  фідах**, навіть якщо на сайті він є. Діє, поки галочку не повернуть.
- Галочка стоїть - наявність як на сайті.
- Товар без картки на сайті (`feed_only`) - в наявності, якщо не `off`.
- Вимкнений товар **лишається у фіді** зі статусом «немає в наявності» (не зникає).

### 4.4 Коли товар не потрапляє у фіди

- комплекти автономного енергоживлення (категорія 11, `EXCLUDED_CATS` у генераторі) - прибрані з усіх фідів 30.10.2026 на прохання шефа; кабельні «Комплекти силових кабелів» (категорія 4) лишаються;
- немає ціни (`price` порожня або ≤ 0);
- немає жодного фото на білому фоні (див. 5.2);
- позиція з ручного списку, якої вже немає на сайті (не `feed_only`);
- для опту і фідів від опту - немає гуртової ціни.

Генератор пише про кожен такий випадок у звіті (журнал запуску GitHub Actions),
а в адмінці під назвою товару видно причину.

## 5. Генератор фідів (`scripts/generate_ultradomik_feed.py`)

Один запуск будує всі фіди. Порядок:

1. Читає товари сайту (`products.json`), ручний список, `prices.json`, `feeds.json`.
2. Для кожної позиції ручного списку - запис фіду з ручних текстів.
3. **Для кожного товару сайту, якого немає в ручному списку - запис з картки
   сайту** (див. 5.1). Так нові товари сайту потрапляють у фіди самі.
4. Перевіряє фото на білий фон, ціну.
5. Пише всі файли фідів, видаляє файли фідів, прибраних в адмінці.
6. Пише `feed_items.json` для адмінки і звіт.

### 5.1 Товари, побудовані з картки сайту

- назва = назва на сайті;
- опис = абзаци опису з сайту (рядки з «•» стають списком `<ul>`);
- характеристики = таблиця характеристик з сайту (HTML-таблиця → список);
- категорія = за типом товару на сайті (`product_type`), див. 5.4;
- виробник = рядок «Виробник» у характеристиках або перше слово назви
  (лише якщо він є в базі виробників Prom);
- артикул = `mpn`;
- ключові слова UA = `merchant_keywords_uk` (або назва), RU = `merchant_keywords_ru`, якщо є.

**Російська мова.** На сайті тексти лише українською, автоматичного перекладу
немає (так вирішено). Тому в таких товарів **немає російського опису**
(`<description>`), російські ключові слова - лише якщо є на сайті, а `<name>`
заповнюється українською назвою (тег потрібен Prom).

### 5.2 Фото тільки на білому фоні

Перевірка: смуга ~2,5 % ширини/висоти по периметру; фото «біле», якщо ≥ 95 %
пікселів цієї смуги мають R, G, B ≥ 240. Фото, що не пройшли, у фід не йдуть.
Перше `<image>` завжди на білому фоні, не більше 10 фото на товар.

Кандидати: фото з прайсу (`assets/images/ultradomik/<id>.*`), білі копії
постачальника (`prom_images`), а для товарів з картки сайту - ще й будь-яке фото
товару на сайті.

### 5.3 Фото комплектів

Комплект («Комплект ...: <інвертор> + <акумулятор>») без білого фото отримує
зібране: генератор знаходить складники за кодом моделі в назві (не за ємністю
на кшталт «230Ah»), бере їхні білі фото, обрізає білі поля і ставить поруч на
білому полотні 1200×1200 (`assets/images/feed-auto/<id>.jpg`). Фото збирається
один раз; щоб перезібрати - видалити файл. Якщо складник не знайдено (наприклад,
модель з назви комплекту відсутня на сайті) - комплект без фото, у фід не йде.

### 5.4 Категорії

У `<catalog>` - групи фіду з фіксованими id (ніколи не перенумеровувати, лише
додавати) і `portal_id` - категорія маркетплейсу Prom. Використовуються лише
категорії Prom, які **не** заблоковані для редагування (інакше Prom ставить
«Автоматично вказана категорія»).

| id | Група | Тип товару на сайті |
|---|---|---|
| 1 | Гібридні інвертори | «інвертори» |
| 2 | Акумулятори | «Акумулятори» |
| 3 | Системи зберігання 2 в 1 | «2 в 1» |
| 4 | Кабельна продукція | «кабелі» |
| 5 | Зарядні станції | «Зарядні станції» |
| 6 | Безперебійники для роутерів | «безперебійного» |
| 7 | АВР | «АВР» |
| 8 | Реле напруги | «Реле напруги» |
| 9 | Таймери | «Таймери» |
| 10 | Лічильники | «Лічильники» |
| 11 | Комплекти автономного енергоживлення | «Комплекти» |
| 12 | Wi-Fi модулі для інверторів | «Wi-Fi» |
| 13 | Інше обладнання | усе інше |

### 5.5 Формат XML (Prom, стиль Price.ua, RU + UA)

```xml
<?xml version="1.0" encoding="UTF-8"?>
<shop>
  <catalog>
    <category id="1" portal_id="501001">Гібридні інвертори</category>
  </catalog>
  <items>
    <item id="152517" selling_type="r">
      <name>…RU…</name>
      <name_ua>…UA…</name_ua>
      <categoryId>1</categoryId>
      <portal_category_id>501001</portal_category_id>
      <priceuah>11483.00</priceuah>
      <available>true</available>
      <vendorCode>PV18-1512VPM II</vendorCode>
      <vendor>MUST</vendor>
      <image>https://…/photo.jpg</image>
      <description><![CDATA[…RU HTML…]]></description>
      <description_ua><![CDATA[…UA HTML…]]></description_ua>
      <keywords>…RU…</keywords>
      <keywords_ua>…UA…</keywords_ua>
    </item>
  </items>
</shop>
```

Обов'язкові правила (перевіряються при кожній генерації):

- **жодного «dfi» / «дфі» / «дфи»** у файлі (у будь-якому регістрі); якщо
  знайдено - файл не пишеться, генерація падає з помилкою;
- ціни **лише в гривнях** (`<priceuah>`), без `<priceusd>`; долари → гривні
  за курсом (для опту - курс з адмінки);
- лише фото на білому фоні;
- `id` товару стабільний між вивантаженнями;
- опис - HTML у `<![CDATA[…]]>`: абзаци, «Де використовується:» (список),
  «Основні характеристики:» (список); `<param>` **не** використовуються
  (Prom перевіряє їх за довідником категорії і позначав як помилку);
- `<vendor>` - лише виробники, що є в базі Prom (MUST, Felicity, Deye, Dyness,
  EcoFlow, KBE), інакше тег не пишеться;
- `vendorCode` ≤ 25 символів, ключові слова ≤ 1024 символи;
- керуючі символи вирізаються, файл перевіряється XML-парсером.

## 6. Адмінка `/prom-admin/`

Одна статична HTML-сторінка (`prom-admin/index.html`, без фреймворків). Не
індексується (`noindex`), браузер її не кешує (`prom-admin/.htaccess`:
`Cache-Control: no-cache, no-store`), щоб після оновлення коду одразу була нова версія.

### 6.1 Вхід

Два рівні:

1. **Вхід в адмінку сайту** (Supabase Auth, email + пароль) - спільна шапка
   `assets/js/admin-shell.js`, як в інших розділах адмінки.
2. **Токен GitHub** (fine-grained, доступ до репозиторію сайту:
   Contents - Read and write). Вводиться один раз, зберігається в
   `localStorage`. Потрібен, бо дані лежать у репозиторії. Якщо токен не
   підходить (401/403/404) - він стирається і форма показується знову.

Поле токена - в окремій `<form autocomplete="off">`, а поле пошуку має
`autocomplete="off"`: інакше Chrome вписує збережений email у пошук і таблиця
порожніє.

### 6.2 Будова сторінки (згори донизу)

**Шапка**: назва, кнопки фільтра категорій (показуються лише ті, де є товари),
пошук за назвою або id.

**Блок «Фіди»** - таблиця фідів:

| Назва | Основа | Від основи, % | Випадкова надбавка, грн | Посилання | |
|---|---|---|---|---|---|
| Роздрібні ціни (основний) | Роздріб | 0% | 1–10 грн | посилання + «Копіювати» | |
| Гуртові ціни (опт) | Опт | ціни вручну | - | посилання + «Копіювати» | |
| *клієнтський фід* | список Роздріб/Опт | поле % | поля від … до | посилання + «Копіювати» | «Зберегти» (з'являється після змін), «Видалити» |

- Під назвою клієнтського фіду - правило словами, напр. «Ціна: ціна роздріб
  +1…+200 грн (випадково для кожного товару)», «Ціна: ціна гурт +16%».
- Біля посилання - «ще формується (1–2 хв)», поки файлу ще немає на сайті
  (HEAD-запит до файлу).
- «Видалити» питає підтвердження: посилання перестане працювати.
- **Новий фід**: назва, основа (від роздрібу / від опту), %, надбавка від/до
  (необов'язково), «Створити». Якщо задано надбавку, відсоток можна не вказувати.
  Файл = `feed/<транслітерація назви>.xml`, унікальний (додається `-2`, `-3`…),
  не може збігатися із зарезервованими (`prom_file.xml`, `feed/opt.xml`,
  `feed.xml`, `feed/bezpeka.xml`, `sitemap.xml`, `prom.xml`).
- Нижче - «Інші фіди сайту» лише з посиланнями.

**Блок «Курс $ для гурту»**: поле курсу (грн за $1), кнопка «Зберегти курс»
(з'являється після зміни; Enter теж зберігає).

**Підказка** - як працюють ціни, автооновлення, гурт і галочка.

**Таблиця товарів**:

| Код (id пост.) | фото | Товар | Ціна роздріб, грн | Ціна гурт, $ | В наявності (усі фіди) | *колонка на кожен клієнтський фід* |
|---|---|---|---|---|---|---|

- «Код»: наш код товару = id постачальника − 140000 (див. docs/B2B.md), під ним - id постачальника.
- «Товар»: назва, категорія; червоним - чому товар не йде у фід.
- «Ціна роздріб» - поле; ціле число > 0 або порожньо.
- «Ціна гурт, $» - поле, до центів (`250,5`); порожньо = 0. Під полем
  «≈ 11 272,5 грн» за збереженим курсом або «у фід опту не йде».
- «В наявності» - галочка (= НЕ `off`). Під нею: «вимкнено у фідах» (знята) або
  «на сайті немає» (стоїть, але на сайті товару немає в наявності).
- Колонки клієнтських фідів - лише показ розрахованої ціни (без випадкових
  1–10 грн основного фіду); для фіду з надбавкою - межі «15 060–15 259».
- Змінений рядок підсвічується; рядок без ціни або з проблемою - напівпрозорий.
- Enter у полі ціни - до того ж поля в наступному рядку, Shift+Enter - у попередньому.
- Якщо фільтр сховав усе - текст «Нічого не знайдено…» і кнопка скинути фільтр.

**Нижня панель** (липка, видно лише при змінах): «Змінено товарів: N»,
«Скасувати», «Зберегти». При спробі закрити сторінку з незбереженими змінами -
попередження браузера.

### 6.3 Збереження (GitHub Contents API)

- **Ціни/гурт/галочка** → `prices.json`. Беремо **свіжий** файл, міняємо лише
  відредаговані товари, `PUT` з `sha`. Якщо той самий товар тим часом змінив
  хтось інший (значення у свіжому файлі ≠ того, що було при завантаженні) -
  не перезаписуємо, просимо оновити сторінку. Якщо файл змінився між читанням і
  записом (409/422) - до 3 повторів.
- **Фіди й курс** → `feeds.json`, так само: свіжий файл → зміна → `PUT`, до 3
  повторів. Невідомі поля файлу зберігаються як є.
- Повідомлення коміту описове: «Адмінка Prom: ціни (товари 152517, …)»,
  «Адмінка Prom: новий фід «…» (+20%)», «Адмінка Prom: курс $ для гурту 41.5».
- Після збереження сторінка перезавантажує дані. Перед створенням фіду чи
  збереженням курсу з незбереженими цінами - підтвердження (вони зникнуть).
- Вміст файлів кодується в base64 з UTF-8 в обидва боки.

## 7. Автоматизація (GitHub Actions)

### 7.1 Після збереження в адмінці - `prom-feed.yml`

Запускається на push у `master`, якщо змінились `prices.json`, `feeds.json`,
`products.json` (ручний список), фото прайсу або сам генератор.

1. `python scripts/generate_ultradomik_feed.py`
2. коміт фідів (`prom_file.xml`, `invertorshop.xml`, `feed/`, `feed_items.json`,
   `feeds_built.json`, `assets/images/feed-auto/`) з `git pull --rebase` перед push;
3. викладка на сервер по SSH (`git pull` у теці сайту) - коміт бота сам не
   запускає деплой.

`concurrency: prom-feed` без скасування - кілька збережень поспіль виконуються
по черзі. Фіди оновлюються на сайті за **1–2 хвилини** після збереження.

### 7.2 Автооновлення сайту - `update.yml`

Тричі на добу, **≈11:10, 15:10, 19:10 за Києвом** (cron в UTC для літнього й
зимового часу; зайвий запуск без змін нічого не комітить):

1. товари постачальника → `products.json` (нові товари з'являються на сайті,
   зниклі - пропадають);
2. `sync_ultradomik_prices.py`: роздрібна ціна й наявність **кожного** товару
   сайту → `prices.json` (`wholesale_usd` і `off` не чіпає; товари без ціни на
   сайті й `feed_only` лишаються з ручними значеннями);
3. генератор фідів - нові товари сайту відразу йдуть в усі фіди;
4. коміт і викладка.

Отже: новий товар на сайті → у фідах при тому ж автооновленні; ручна роздрібна
ціна діє до наступного автооновлення; гурт, курс, галочка й налаштування фідів -
поки їх не змінять в адмінці.

## 8. Що адаптувати на іншому сайті

- джерело товарів сайту (тут `products.json` з фіда постачальника) і поля:
  `id`, `title`, `price` («14926 UAH»), `availability`, `product_type`,
  `description`, `specs` (HTML-таблиця), `mpn`, `image_link`,
  `additional_images`, `prom_images`, `merchant_keywords_uk/ru`;
- назви файлів і тек (`data/ultradomik/`, `prom_file.xml`, `feed/`);
- категорії Prom (`portal_id`) і зіставлення з типами товарів сайту;
- список виробників, які є в базі Prom;
- репозиторій/гілка в адмінці (`REPO`, `BRANCH`), домен (`SITE`);
- вхід в адмінку (тут Supabase через спільну шапку - можна лишити тільки токен GitHub);
- деплой (тут SSH + `git pull`; на GitHub Pages - окремий крок не потрібен);
- розклад автооновлення під графік постачальника.
